# ADR-023 · Core同库财务、不可变价格版本与固定锁序

> 状态：设计已选定，待用户P0最终冻结；工程行为未验证。决策不意味着运行测试通过。

## 1. 背景

Quota、采购预算、TeamGrant和调用结算需要可审计、无部分提交的原子事实。

## 2. 需要解决的问题

拆不同服务/表后单靠缓存预扣会出现未付费出站或一边扣款失败。

## 3. 候选方案

1. 跨微服务Saga/分布式事务
2. Core MySQL短事务锁真实预算/Reservation/Ledger/Outbox并保留价格版本（选择）
3. Redis计数当权威预算

## 4. 最终方案

采用Core MySQL资金同库事务；每个真实出站仅一个Permission、Price、Budget快照和唯一Permit。

## 5. 选择原因

相同Employee/Agent可能并发共享预算，必须以行锁与唯一约束避免超发；出站HTTP不在事务内执行。

## 6. 优点

可审计、可解释，失败时DB能回滚，不要求Broker/Redis在线完成资金提交。

## 7. 缺点与引入的复杂度

锁顺序、死锁重试、超额与未知费用账务复杂，需真实MySQL并发/故障测试。

## 8. 对未来的影响

如未来出现跨库真实需求再评估拆分；不为技术栈而加分布式事务。
