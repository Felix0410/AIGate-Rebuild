# ADR-031 · Core Outbox+RabbitMQ+FinOps Inbox与双Build

> 状态：设计已选定，待用户P0最终冻结；工程行为未验证。决策不意味着运行测试通过。

## 1. 背景

P11报表源自已提交账务/Grant和真实GPU费用，不能影响Core余额且要承受Broker重复/漏投。

## 2. 需要解决的问题

Broker不是资金事务的一部分，直接事务内publish会出现数据库COMMIT与消息投递不一致。

## 3. 候选方案

1. FinOps直接查询Core数据库，权限与性能边界不清
2. Core直接publish RabbitMQ，没有持久outbox
3. Core本地Outbox+RabbitMQ至少一次+FinOps Inbox/Fact/Aggregate+Manifest核缺+双Build（选择）

## 4. 最终方案

Core唯一财务写主，FinOps有独立finops_db；SchemaV1事件分类、PayloadDigest、最多5000 SnapshotManifest、安全补拉与CAS投影切换。

## 5. 选择原因

最终一致且可审计，迟到更正以新revision/delta追加，不覆盖已发表事实。

## 6. 优点

允许MQ暂时不可用又不丢账、重建可验证来源完整性。

## 7. 缺点与引入的复杂度

RabbitMQ/Inbox/Manifest/双数据库引入一致性与运维复杂度，读模型不再实时。

## 8. 对未来的影响

真实窗口超过5000需要分页/稳定快照新设计；不得暗中变成跨库SELECT或静默FRESH。
