# ADR-007 · Java21+Spring Boot4技术基线

> 状态：设计已选定，待用户P0最终冻结；工程行为未验证。决策不意味着运行测试通过。

## 1. 背景

P1要独立启动Gateway/Core，后续财务需要事务、低耦合DAO和真实SQL迁移。

## 2. 需要解决的问题

不受约束地更换框架与容器版本会使本地AI自己选择兼容组合，造成难以复现的环境。

## 3. 候选方案

1. Java21 + Boot4.1.1 + Cloud2025.1.3 + Gateway Server WebMVC + MyBatis-Plus3.5.17 + MySQL8.4/Flyway + Redis8.4 + MavenWrapper3.9.16（选择）
2. Boot3旧生态但与已批准路线不一致
3. 自研JDK HTTP网关和ORM：工作量大且偏离业务

## 4. 最终方案

选择Java21 + Boot4.1.1 + Cloud2025.1.3 + Gateway5.0.3 Server WebMVC + MyBatis-Plus3.5.17 + MySQL8.4/Flyway + MavenWrapper3.9.16。原2025.1.2已经官方支持Boot4.1，但2025.1.3包含额外安全修复；在尚未冻结的P0阶段明确修订补丁线。P0的真实兼容PoC先于大规模实现，Boot4.1.2（2026-10-22刚发布）只作为后续补丁候选，不能未经验证直接升级。

## 5. 选择原因

Spring事务/MySQL适合同库资金，MVC网关与Core各自职责清晰，减少首期引入项。

## 6. 优点

统一JDK与Starter管理，ORM只作为简化Mapper不免除SQL设计。

## 7. 缺点与引入的复杂度

版本之间可能有Starter/BOM冲突，需要真实构建、Gateway路由、Flyway和Testcontainers验证；无PASS不能说兼容已证实。

## 8. 对未来的影响

任何版本调整须提交依赖树、必要PoC和总控变更记录；不得执行AI自动升级框架。

## 9. 相关合同与验证

2026-10-23已核对官方Boot、Cloud、Gateway、MyBatis-Plus、Flyway/Maven兼容声明，见[P0技术兼容检查](../tests/p00-technology-compatibility.md)。当前环境只有Java21，没有Maven/Docker或可访问Maven Central的网络；本ADR仍无任何PoC真实PASS。

[系统架构](../03-architecture.md) · [Database](../05-database-design.md) · [Runtime](../07-runtime-protocols.md) · [测试](../09-test-plan.md)。本ADR无独立测试PASS；对应Phase首次实现时提供真实证据。
