# ADR-029 · 供应商可信Usage与费用硬上界

> 状态：设计已选定，待用户P0最终冻结；工程行为未验证。决策不意味着运行测试通过。

## 1. 背景

外部OpenAI格式兼容不能证明其tokenizer、隐藏计费类别、cached折扣与输出上界一致，P7会产生真实采购成本。

## 2. 需要解决的问题

若用字符数/HTTP200/未知费用按0估算，会允许公司采购预算失控。

## 3. 候选方案

1. 任何兼容接口都直接接入并事后对账
2. 全Provider SDK动态识别收费，由执行AI推断
3. 只允许有真实证据的文本INPUT/OUTPUT双费率Deployment，其它拒新收费（选择）

## 4. 最终方案

V3部署持久化AdapterCompatibility与批准证据，Gateway依据Core唯一快照，Preflight按真实保守Token上界预留，可信Provider usage才结算。

## 5. 选择原因

实际供应商外部收费无全局分布式事务，硬上界加风险保留是可解释的最小安全方案。

## 6. 优点

支持业务可付费调用且对未知不伪造免费；不提前建立复杂Token定价引擎。

## 7. 缺点与引入的复杂度

首版Provider覆盖面小、需真实Tokenizer/协议证据；绝对费用不可由公司MySQL单方面保证。

## 8. 对未来的影响

缓存独立费率/ReasoningToken/工具附加费扩展时先升级价格/风险Schema与ADR。
