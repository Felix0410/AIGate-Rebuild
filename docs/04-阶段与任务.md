# AIGate 开发路线与任务计划

> **先完成整体设计，再逐阶段交给本地 AI 快速编码。** 本轮重建进度从 P0 开始：旧项目 P1～P3 的实现与测试记录一律不算本项目完成。用户批准某个 Phase 的开工和关闭之前不得自行前进。

## 一、Phase 路线（P0～P12）

下表各行依次给出 **业务目标 → 范围/主流程 → 架构任务 → 验收要求 → 知识点**。详细数据/API 合同统一参见《01-业务与规则.md》《02-架构与技术.md》《03-数据与接口.md》，本地 AI 不得替换已确定规则。

| Phase | 业务目标 / 主流程 | 主要任务（先 Happy Path） | Acceptance Criteria / Knowledge Points |
|---|---|---|---|
| **P0 当前** | 完成全局产品、业务和技术设计 | 冻结架构、数据、接口、执行任务与测试矩阵；用户评审 | 中文 docs 内部一致，未授权编码；需求拆解、架构取舍 |
| **P1** | 搭建可运行 Java 项目：管理员管理 Team 与 Employee | Maven/Boot/MySQL/Flyway、管理认证、CRUD、Compose、Testcontainers、CI | 干净环境启动，迁移与 REST 集成测试通过；MVC、DI、MyBatis、数据库 |
| **P2** | 登记既有 Agent、Provider、逻辑 Model、Deployment，打通同步模型代理 | Key 签发/撤销、Adapter、Provider HTTP、受控端点与密钥保护 | Fake Provider 成功/拒绝/超时 E2E；HTTP、Security、Adapter 模式 |
| **P3** | 追踪每次模型调用，定位失败 | Invocation 元数据/状态/trace、查询分页、数据保留 | 成功/超时/异常都能查到，不存 Prompt；SQL 索引、状态机 |
| **P4** | 员工与 Agent 双身份及 Agent/Model 权限 | 员工凭证、双认证、RBAC、Employee-Agent 权限、Agent Model 白名单 | 无员工 Key 或伪造 employeeId 不能出站；Principal、安全过滤链 |
| **P5** | 可靠积分计量与个人周额度 | 价格版本、Token、免费/基础周桶、Reservation/Allocation/Ledger、结算、待核对 | 并发不超扣、幂等、周重置正确、未知用量不记零；ACID、行锁、BigDecimal |
| **P6** | 团队申请/审批/主动补充积分 | Team Pool、Grant、跨团队发放、到期清理、资金来源优先消费 | 发放即扣、重复审批不双扣、到期不退；事务、唯一键、状态机 |
| **P7** | 有资金硬边界的限流/正常/紧急档基础治理 | 公司保底和个人周硬限额、授权保底模型、两副本限流与 Redis/Lua | 超出公司预算 0 次新收费出站、双实例同一全局限流；Lua、并发 |
| **P8** | 同模型多 Deployment 路由与 SSE | 健康/权重/延迟/成本、MVC SSE、断连取消、Micrometer/Grafana | 路由命中受允许部署、SSE 断线正确待核对、观测活跃连接；网络 I/O、监控 |
| **P9** | 紧急任务获得有界资源保障 | 紧急审批、指定 Employee/Agent/Task/过期、优先级和预算 | 没审批不可跳级，紧急预算不透支，混合负载不无限饥饿；队列、舱壁 |
| **P10** | 企业 AI 请求安全治理 | 数据分级、敏感规则、策略版本、出站前判定、审计与例外 | 危险请求在 Provider 前拒绝、原文不写审计；规则/缓存一致性 |
| **P11** | FinOps 成本分析与消息可靠性 | 三口径报表、日报趋势/阈值；MySQL Outbox、RabbitMQ、Inbox 幂等、重试/死信 | MQ 停机仍能完成账务，恢复后统计正确；消息确认、最终一致 |
| **P12** | 完整生产可靠性与条件式微服务演进 | Docker/CI/负载/JFR、单体 1vs2 副本、故障演练、按 ADR 决定拆服务 | 提供可复现性能/账务/故障报告；JVM、分布式系统、服务边界 |

**阶段排序已确定**，但某 Phase 的编码文件列表和单次提交工作包仍需在该 Phase 开始前由总控从本文与业务/API 合同进一步冻结。这个步骤是总控责任，不交给本地 AI 自由拆分。

## 二、分阶段编码工作包（交付顺序已定）

**P1**：T01 创建新 Boot 工程、Maven、Compose、MySQL/Flyway、Admin 引导身份与测试环境；T02 Team/Employee 表、Repository、DTO、Controller、Service；T03 权限、无效参数、Testcontainers、CI 和 Code Review。

**P2**：T01 Application/Agent Key 的摘要和撤销；T02 Provider/Model/Deployment/价表基础配置与 SSRF 防护；T03 RestClient 代理 Fake Provider 同步调用、超时/错误/密钥不泄漏。P2/P3 的 Runtime 调用仅对测试 Mock 开放；**真实收费 Provider 路径须等 P4 双身份认证通过才放开**。

**P3**：T01 调用记录 schema、状态/耗时/traceId；T02 成功/失败/超时写入、分页/过滤/分批保留及测试。此阶段记录不是可扣款账本。

**P4**：T01 员工 Key 产生/撤销、凭证摘要和 Principal；T02 Employee-Agent/Agent-Model 双权限和管理角色；T03 伪造 Employee、跨 Agent/Model、撤销和 Provider 零出站测试。

**P5**：T01 双价格版本、Token 类别、公司时区周周期；T02 周额度、预留、Allocation、结算、流水和待核对状态，事务锁顺序；T03 Fake Provider 可信 usage、并发、幂等、超时和风险上界测试。

**P6**：T01 Team Pool 与申请审批/主动发放；T02 发放同事务扣池和 Grant、跨 Team 归属；T03 Grant 有效期、优先消费、重复审批/过期不返还的集成测试。

**P7**：T01 受控企业保底和员工周硬上限、授权保底 Model；T02 普通/限流/紧急基础档及 JVM 单实例基线；T03 双实例共享速率问题复现并加 Redis/Lua、Redis 故障测试。

**P8**：T01 Deployment 路由选择/健康；T02 SSE 透传/取消/末尾 usage/未知待核对；T03 Prometheus/Grafana、活跃连接和不同部署压力压测。

**P9**：T01 紧急申请/审批和独立资金池；T02 任务优先调度、过期校验/并发与公平性测试。

**P10**：T01 安全政策分类/版本/发布；T02 出站前敏感字段/密钥检测与策略拒绝；T03 安全元数据审计、策略失效/例外 E2E。

**P11**：T01 从权威已确认流水生成三口径报表；T02 同事务 Outbox、RabbitMQ Publisher Confirm、ACK、重复消费 Inbox、重试/DLQ；T03 阈值告警、MQ 中断恢复、事件重放和三账对账。

**P12**：T01 完整交付/性能基线、两副本 SSE/DB 正确性演练；T02 列出可证实独立扩容/故障隔离问题并分析服务拆分；T03 若 ADR 通过才独立拆 Gateway/Control/Quota/Governance/FinOps 中必要部分、补 RPC/可观测/故障测试；可以有证据地选择不拆。

## 三、本地 AI 每个单次工作包必须拿到什么

总控交付：**Business Goal、Scope（含明确不做）、Main Flow、Architecture、准确的表/字段/索引与 API/DTO、允许修改的文件、新依赖的七问与引入条件、异常/幂等规则、测试命令与验收样例**。工作包引用本仓库当前 docs，但不能要求本地 AI “自行决定合理实现”。

本地 AI 实施后回复：TASK、实际改动路径、表/接口清单、执行命令和测试数量、Git SHA、可复现运行方法、发现的问题及技术债；**不自行改 docs、扩大技术栈或开始下一个 Phase**。

## 四、Phase Closeout 质量门禁

每阶段：①功能检查 ②Code Review ③测试检查 ④架构检查 ⑤技术债 ⑥更新进度 ⑦更新架构 ⑧必要 ADR ⑨知识复盘 ⑩面试表达。完成之后等待用户批准才进入下一阶段。

用户主要学习真实的业务和技术，而不是亲手写完每行代码。出现新技术先讲**业务背景→问题→是什么→为什么出现→原理→执行流程→相似方案→AIGate 用途**，最后再阅读本地 AI 代码。
