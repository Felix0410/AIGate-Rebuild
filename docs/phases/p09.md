# P9 · 受控LOW保底与本地基础补贴

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

正常路线不可用时，在员工事先同意且管理员批准下选择更低成本替代模型或本地补贴，不无止境重发。

## Scope（范围）

Core V9五表与Invocation ALTER；CompanyFallbackPool、Employee周Cap、LocalTokenQuota、FallbackRoutePolicy；RPC CanonicalV2。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

Client声明ALLOW_APPROVED→Core核对Agent特定FallbackPolicy/跨Model ACL/安全/真实企业池和员工周cap→只选择一次目标与资金来源→正常P7 Permit链路。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v09.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

V9及Invocation真实模型/funding_mode快照；三类保底账户与管理API；RPCv2；低成本/成本单位安全比较与单次选择测试。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

v1无fallback同意不得LOW；不从第三方失败再切另一个收费Provider重复外发；历史实际Model与资金快照可解释；本地token不伪造供应商货币。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。

## Knowledge Points（学习重点）
