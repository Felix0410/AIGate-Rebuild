# P5 · 团队资金池与跨Team Grant

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

Team Manager受控发放积分到具体员工，员工使用Grant时保持真实发行Team归属。

## Scope（范围）

Core V5三表；TeamPool、TeamGrant、发行receipt；FEFO分配，发行一次消耗TeamPool；理由和撤销审计。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

Admin设置TeamPool → 有权Manager发送recipient/points/期限/原因 → 事务锁Pool发行Grant及Ledger/Outbox → 后续预留按过期时间FEFO → 结算原Grant或到期阻止新用。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v05.md)；外部接口：[相关API](../api/p04-p06.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。
