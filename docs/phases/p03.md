## Business Goal（业务目标）

管理员明确登记逻辑模型和真实部署、可审计价格与加密Provider凭证，让下一Phase可安全引用。

## Scope（范围）

Core V3七表；Provider/LogicalModel/Deployment；POINTS价格、采购原币种价双版本；AgentModel ACL；HostPolicy/CapabilityProfile封闭JSON；AES-GCM；适配证据。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

登记Provider和受控Host/Region → 创建Model和Deployment DRAFT → 配置Adapter证据与真实价草稿 → 独立发布冻结版 → 加密管理ProviderCredential → 授权AgentModel。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v03.md)；外部接口：[相关API](../api/p01-p03.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

创建Catalog API、价格CAS、SSRF HostPolicy验证、Provider凭证一次写入AES-GCM/幂等、Model/Deployment/AgentModel ACL；不得真实发送付费Provider。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。本次用户明确授权执行者补齐 P3 合同并同步正式文档；仍沿用现有技术栈和七表设计，不提前实现未来 Phase。

## Acceptance Criteria（验收标准）

价格旧修订不可修改；ProviderSecret不回显且4096字节合法加密存入VARBINARY8192；未知Capability/Host参数400；P3创建Deployment无capacityPoolId；缺完整出站证据不能ACTIVE收费。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。
