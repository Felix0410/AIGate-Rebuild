# P12 · 多副本、全局阻断与灾难恢复

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

多个Gateway/Core在真实故障下仍一致阻止新未授权付费请求，并可在证据齐全后安全恢复。

## Scope（范围）

Core V11新增运营单例表和V1审计Receipt ALTER；Gateway/Core多副本；readiness-probes和recovery-review；压测/指标；FinOps不影响Core资金。Core V11运营单例表属于Core迁移，而非FinOps。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

管理员block→Core V11单例独占版本修改→新Permit共享行锁读到BLOCK拒绝→故障期间保留旧资金风险→Core真实readiness六项检查生成审计HMAC证据→另次review安全CAS增epoch→多Gateway恢复。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core + FinOps多副本；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v11.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

V11迁移；全局Block/ReadinessProbe/RecoveryReview API；旧版Core混合部署门禁；双Gateway/Core容灾、Redis/DB恢复、实际锁热点压测与观测；审计权限负例。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

旧代码不得绕过V11；证据过期/伪造不恢复；BLOCK提交后不产生新的许可；未证明的供应商费用不会变0；真实流式中断可查账；性能数据有环境标识。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。

## Knowledge Points（学习重点）

分布式故障、锁相容性、RPO/RTO、观测/回滚与多实例隔离。
