# P11 · 异步成本分析FinOps

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

财务能按正确权限查看五类可靠成本事实，不让报表对Core金额产生副作用。

## Scope（范围）

第三应用aigate-finops与finops_db V1七表；RabbitMQ Outbox/Inbox/Manifest/双Build；当前RBAC typedScope；运营费用双人审批。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

Core真实结算/Grant发行同事务Outbox→Broker至少一次→FinOps独立Inbox去重→Fact/Aggregate→Manifest核漏与补拉→FinOps Scope查询；独立本地GPU费用另一管理员审批。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core + FinOps；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/finops-v01.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

FinOps独立DB/依赖/Consumer；五Event payload格式+摘要/版本；SourceManifest≤5000；Build切换；Scope/Team快照；运营费用Draft/Approve/Void持久幂等。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

重复MQ不双计、漏事件不FRESH、Team越权聚合拒绝、跨币种不加总、Draft初始revision1、重建同Key不重复Build、FinOps故障Core账务仍正确。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。
