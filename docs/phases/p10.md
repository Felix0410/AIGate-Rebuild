# P10 · 紧急审批、专用企业池和4:2:1调度

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

真正紧急任务可由不同审批人批准高优先级，但不能绕过数据安全/采购预算或占满正常资源。

## Scope（范围）

Core V10五表/Invocation ALTER；EmergencyRequest不可变申请模型JSON、AuthorizationModel子集、唯一ActiveSlot、EmergencyPool；RPCv3 TaskRef Header；Redis三档4:2:1。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

受权Employee申请Task/Model子集/有效期→另一Admin审核限额→同一Employee+Agent+Task只存唯一有效Slot→Runtime携成对受控Header→Core锁当前授权+专用资金→Redis按加权队列授位。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v10.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

V10 ALTER；双人审批API/限额；emergency_request.version与requested_model_ids_json；P10 RPCv3签名；Pool Scheduler4:2:1；真正竞态/断线测试。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

不得自批；审批模型只能请求子集；v1/v2请求不能伪紧急；唯一Slot/旧任务冻结可查；持续饱和时NORMAL和LOW不会饿死；已ACTIVE不抢占。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。
