# P7 · 真实AI调用、容量池与一次性Permit

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

员工通过双Key调用真实受控Chat JSON/SSE，任何可能收费的外发有硬费用上界与唯一Core Permit。

## Scope（范围）

Core V7五表，受控CapacityPool与绑定、Gateway Provider Adapter、Redis同slot Lua NORMAL队列、Core6RPC、SSE/Report/Unknown；P7不使用P12 probes。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

双Key请求→Core Preflight→Redis排队ACTIVE→Core独立INSPECT与锁定安全/价格/双账户→唯一Permit COMMIT→一次出站→可信usage结算或UNKNOWN→Ledger/Outbox。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v07.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

V7及旧Deployment FK；Pool创建/绑定/激活/阻断；V1Canonical HMAC；真实Redis Lua Queue/Lease/RPM；ProviderTextAdapter/SSRF/JSON/SSE；结果报告与对账；FakeProvider端到端失败注入。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

两个Gateway同池不超容；ACK lost不二次Provider；未知usage不释放钱；Redis runId冷重启阻止新Permit；SSE断流后风险仍真实；池默认DISABLED，真实证据才开。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。

## Knowledge Points（学习重点）

Redis Lua原子性、HMAC版本、HTTP半开、SSE背压、双账Reservation、有限一次I/O。

## Dependencies & Risks

前置Phase必须已经用户签收；运行阶段遇到合同冲突，执行AI停止该子包反馈，先由总控修正[设计总览](../README.md)与相关协议、再继续。不得凭Fake费用/Provider凭证/安全区域配置声称已获生产审批。
