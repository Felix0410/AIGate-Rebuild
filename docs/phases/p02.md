## Business Goal（业务目标）

员工在获授权Agent上代表企业运行，而不是所有Team成员自动有权限。

## Scope（范围）

Core V2四表；Agent及1:1应用；agk_和empk_分别签发/轮换/吊销；EmployeeAgent ACL；内部身份验证服务。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

平台Admin登记Agent → 签发AgentKey/EmployeeKey → 授予EmployeeAgent → Core每次验证两Key和最新ACL/OwnerTeam ACTIVE → 失败即拒绝。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v02.md)；外部接口：[相关API](../api/p01-p03.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

建立Agent CRUD；两类Key安全签发与最多两把当前可认证Key；owner级唯一receipt、密钥Pepper；ACL PUT/DELETE幂等；扩Core内网验证DTO；真实迁移和测试。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

不同前缀Key不能混用；吊销/过期/Team禁用立即影响下次调用；跨Agent缺ACL返回403；重放签发不再次回明文；并发轮换不超发。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。
