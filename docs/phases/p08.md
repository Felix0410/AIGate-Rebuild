# P8 · 同逻辑模型动态健康路由

> 状态：NOT STARTED；设计候选已审；真实代码和测试尚未运行。本地AI只有在用户批准本Phase后才可执行。

## Business Goal（业务目标）

同一LogicalModel多个Deployment之间按安全硬过滤和运行健康合理调度，不改变已承诺的模型和资金语义。

## Scope（范围）

Core V8两表及Deployment健康字段；RoutingPolicy revision；健康窗口与半开探测；同模型最多一次合法重选。

**明确不做**：不提前实现未来Phase；不改变三服务架构或数据库归属；不因测试方便弱化认证、账务和安全约束。

## Main Flow（核心流程）

当前安全/部署硬过滤 → 读取有证据健康统计 → 评分选Deployment → ACTIVE/Permit前允许一次受控重选 → 结算锁定实际Deployment。

## Architecture（架构/数据所有权）

- 当前应用：Gateway + Core；身份与资金真正主写仍是Core MySQL。
- 数据迁移：[本Phase数据库规范](../database/core-v08.md)；外部接口：[相关API](../api/p07-p12.md)；[Gateway Method白名单](../api/gateway-routes.md)。
- 强制不变量：调用/资源/金额不得绕过本Phase已有前提。长I/O/Scanner/SSE不在MySQL资金锁内执行。

## Tasks（给本地AI的精确任务范围）

V8迁移；受控健康Probe/状态；路由策略创建发布双CAS与Model.version；健康查询；边界限次重选E2E。

**交付文件由本地AI完成**：业务Java/控制器/DTO/Mapper/服务、Flyway迁移、必要的Redis Lua/消息及Adapter、单测/集成测试/配置/CI，以及真实执行日志。总控负责本项目正式设计文档更新，不让本地AI选择新技术。

## Acceptance Criteria（验收标准）

无健康证据UNKNOWN不伪造0；不跨币种直接比较不可比采购价；已Permit不再改目标；并发Publish只有一笔；不能绕过P7双账和治理。

必须同时满足：
1. 当前业务块全部正常与非法输入路径；鉴权/RBAC与未知字段/状态检查。
2. 真实迁移、事务并发、重试幂等与故障状态；未设计异常处理不能默默返回成功。
3. [对应阶段测试](../09-test-plan.md)的真实PASS/FAIL/SKIP及可复现命令；无环境则记BLOCKED而非PASS。
4. Code Review、架构检查、技术债、Progress/ADR如需、知识点与面试表达；用户批准方可下一Phase。

## Knowledge Points（学习重点）

EWMA/窗口统计、熔断/半开、模型身份与部署弹性、乐观锁发布。

## Dependencies & Risks

前置Phase必须已经用户签收；运行阶段遇到合同冲突，执行AI停止该子包反馈，先由总控修正[设计总览](../README.md)与相关协议、再继续。不得凭Fake费用/Provider凭证/安全区域配置声称已获生产审批。
