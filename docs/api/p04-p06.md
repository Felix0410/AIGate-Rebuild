# 管理API · P4～P6（Quota、Grant、Governance）

> 文档性质：**唯一实施合同候选**。所有字段、API、状态、错误、鉴权由Core授权校验，严格遵循[API总约定](../06-api-design.md)。真实HTTP/集成测试NOT RUN。

## 1. P4～P6字段、权限与成功失败约束


本分册是P4～P6的正式字段级实现合同；历史Dxx草稿不再作为实现输入，不创建新业务、更不新增微服务。路径中 `{month}` 严格 `yyyy-MM`、`{weekStart}`/`{periodStart}` 严格 `yyyy-MM-dd` 并按公司配置 ZoneId 的周一00:00/自然月边界换算 UTC；禁止客户端传任意 Instant 绕开周期窗口。资金金额只接受具有完整固定刻度的十进制字符串（POINTS 6位、采购币种8位；允许整数部分不补0，响应总是格式化至固定位数），不接受JSON number/科学计数/负值。所有写入对象禁止额外字段/显式null，CAS版本必须为非负Long；路径作用域和真正可查询数据由 Core 当前身份与授权决定，所有写入+审计同本地事务。

## P4 Quota / ProviderBudget / FinanceOperation

| Method + Path | 必须/允许参数 | 返回与业务不变量 |
|---|---|---|
| POST /api/v1/quotas/policies | `{scopeType:"AGENT_WEEK"\|"EMPLOYEE_WEEK",scopeId:long,weeklyLimitPoints:decimal6,effectiveFrom:instant}`；AGENT_WEEK的scopeId为真实Agent id，EMPLOYEE_WEEK的scopeId=0作为统一公司基础周策略；服务端分配revision | 201 `QuotaPolicyDTO`（id,scopeType,scopeId,weeklyLimitPoints,revision,status:"DRAFT",effectiveFrom,createdAt）；仅Admin；不改已存在周桶 |
| POST /api/v1/quotas/policies/{policyId}/publish | `{expectedRevision:positiveInt}` | 200 `QuotaPolicyDTO(status:"ACTIVE")`；在锁定scope/版本后CAS、旧政策 RETIRED，错误revision 409 |
| GET /api/v1/quotas/policies | scopeType?,scopeId?,status?,page,size | 200 Page<QuotaPolicyDTO>，按id ASC，只有Admin |
| GET /api/v1/employees/{employeeId}/quotas | at?=UTC instant（默认Core当前时间） | 200 `{employeeId,at,agentWeekly:[{agentId,limitPoints,usedPoints,reservedPoints,availablePoints,periodStart,periodEnd}],employeeWeekly:{limitPoints,usedPoints,reservedPoints,availablePoints,periodStart,periodEnd}}`；管理员查询；无生效策略不能假造无限积分 |
| PUT /api/v1/provider-budgets/{currency}/{month} | `{limitAmount:decimal8,normalLimitAmount:decimal8,emergencyLimitAmount:decimal8,expectedVersion:long\|null}`，**仅此接口**允许预定义的创建操作传 expectedVersion=null；更新必传非负long | 首次201、更新200 `ProviderBudgetDTO`（currency,month,limitAmount,normalLimitAmount,emergencyLimitAmount,settledAmount,reservedAmount,riskState,version）；已使用/预留不可低于现额；normal+emergency≤total |
| GET /api/v1/provider-budgets | currency?,month?,page,size | 200 Page<ProviderBudgetDTO>，全部采购货币按币种各自显示，不跨币种加总 |
| GET /api/v1/provider-budgets/{currency}/{month} | 无 | 200 ProviderBudgetDTO；无记录404（不是0预算成功响应） |
| GET /api/v1/finance-operations/{operationKey} | 操作键8～128受控ASCII，路径进行严格百分号解码一次 | 200 `{operationKey,status,employeeId,agentId,logicalModelId,serviceClass,pointsPriceVersionId,providerPriceVersionId,currency,maxPoints,maxCurrencyAmount,pointsReserved,pointsSettled,providerReserved,providerSettled,usageEvidencePresent,createdAt,updatedAt}`，金额允许null表示不适用/未知；不回原Prompt/Key/可信证据明文 |

`QuotaPolicyDTO` 多字段不默认返回复杂嵌套 policy JSON；P4 普通预算修改只针对已明确公司实际审批的额度，例子中的金额都为 Fake。P4 的 FinanceOperation GET 是**管理诊断**，不是可供前端任意创建真实收费的公网 Reserve API。P4测试Facade仍只能使用假Provider evidence，真实收费P7才对接。P4发布策略变化只影响未来周桶，绝不回写已有 bucket limit/period。

**P4固定样例**：

~~~json
{"limitAmount":"0.10000000","normalLimitAmount":"0.08000000","emergencyLimitAmount":"0.02000000","expectedVersion":null}
~~~

首次 `PUT /api/v1/provider-budgets/USD/2026-10` 返回201：
~~~json
{"currency":"USD","month":"2026-10","limitAmount":"0.10000000","normalLimitAmount":"0.08000000","emergencyLimitAmount":"0.02000000","settledAmount":"0.00000000","reservedAmount":"0.00000000","riskState":"ACTIVE","version":0}
~~~
更新时携旧 version、下调小于 `settled+reserved` 必须409 INVALID_STATE；传 `"normalLimitAmount":"0.09000000"` 且 `emergencyLimitAmount="0.02000000"` 时 400/409预算分区和不能超过总额；真实DB CHECK未单独证明两表之和，必须父行锁和对应测试。

## P5 TeamPool/Grant

| Method + Path | Body / Query | 响应、权限、状态 |
|---|---|---|
| PUT /api/v1/teams/{teamId}/pool/{periodStart} | `{limitPoints:decimal6,periodEnd:localDate,expectedVersion:long\|null}`（创建null；更新必须版本） | 201/200 TeamPoolDTO；仅Admin，periodEnd>periodStart；不可低于 issued+reservedIssue |
| GET /api/v1/teams/{teamId}/pool | periodStart必填localDate | 200 TeamPoolDTO；Admin或此Team Manager |
| POST /api/v1/teams/{teamId}/grants | Header Idempotency-Key + `{recipientEmployeeId:long,points:positiveDecimal6,expiresAt:instant,reasonCode:string}` | 201 `GrantDTO`；Admin或issuerTeam Manager；同 operationKey 重放409并回安全GrantId，不重扣Pool |
| GET /api/v1/teams/{teamId}/grants | status?,page,size | 200 Page<GrantDTO>；按issuerTeamId授权/SQL范围过滤 |
| GET /api/v1/employees/me/grants | page,size,status? | 200 Page<GrantDTO>；当前 mgt_ 的本人 Employee，不接受自报employeeId |
| POST /api/v1/teams/{teamId}/grants/{grantId}/revoke | `{reasonCode:string}`，不允许任意手填 refundPoints | 204；只禁止新 Grant Reservation，已发TeamPool不退款，旧Reservation照常结算 |

`TeamPoolDTO={teamId,periodStart,periodEnd,limitPoints,issuedPoints,reservedIssuePoints,availablePoints,status,version,updatedAt}`；`GrantDTO={grantId,issuerTeamId,recipientEmployeeId,issuedPoints,usedPoints,reservedPoints,availablePoints,expiresAt,issuedAt,status,version}`。除本组GET外，普通 Employee 无权限查询其他人Grant，TeamManager 跨Team发给员工时依旧只能看本方发行明细；Grant可用=issued-used-reserved且到期不允许新使用（查询可以显示实际原账与 `availablePoints`，此时availablePoints=0但历史未消费额不消失）。

**P5固定样例**：

~~~json
{"recipientEmployeeId":202,"points":"100.000000","expiresAt":"2026-11-01T00:00:00Z","reasonCode":"TEAM_ALLOCATION"}
~~~

首次201：
~~~json
{"grantId":51,"issuerTeamId":5,"recipientEmployeeId":202,"issuedPoints":"100.000000","usedPoints":"0.000000","reservedPoints":"0.000000","availablePoints":"100.000000","expiresAt":"2026-11-01T00:00:00Z","issuedAt":"2026-10-22T05:00:00Z","status":"ACTIVE","version":0}
~~~

## P6 Governance/安全审批

**最小安全角色**：GLOBAL POLICY_EDITOR创建并提交 Policy Draft；GLOBAL SECURITY_APPROVER 审核/批准/发布（同一草稿不得自审），RoleAssignment通过V6显式CHECK更新；平台管理员管理角色不默认突破安全双人原则。有效 mgt_ 只是认证，不是数据内容例外。申请例外的 Employee 身份要来自Core签名管理凭证本人，不能由客户端body冒充他人。

| Method + Path | 请求 Body / Query | 成功、必须拒绝 |
|---|---|---|
| POST /api/v1/governance/policies/drafts | `{baseRevision:long\|null,classificationRules:RuleV1[],egressMatrix:EgressV1[],outputReviewRules:OutputRuleV1[],reason:string}` | 201 `{revisionId,revision,version:0,status:"DRAFT"}`；Editor且审计 |
| POST /api/v1/governance/policies/{revisionId}/submit | **无body** | 200 `{revisionId,status:"UNDER_REVIEW"}`；仅原Editor或有Edit角色操作者提交一次 |
| POST /api/v1/governance/policies/{revisionId}/review | `{decision:"APPROVE"\|"REJECT",reasonCode:string,expectedVersion:long}` | 200 `{revisionId,status:"APPROVED"\|"REJECTED",version}`；SecurityApprover≠创建人 |
| POST /api/v1/governance/policies/{revisionId}/publish | `{expectedPolicyVersion:long,expectedActiveRevisionId:long\|null}`；expectedPolicyVersion须等于GET active的`policyVersion`，初始无已发布策略时为0且expectedActiveRevisionId=null | 200 `{revisionId,revision,status:"PUBLISHED",policyVersion,publishedAt}`；已 APPROVED；持governance_policy父行锁比较version及active pointer，双CAS更新、旧版标SUPERSEDED |
| GET /api/v1/governance/policies/active | 无 | 已发布返回200 `{revisionId,revision,status:"PUBLISHED",policyVersion,publishedAt}`；尚未发布但policy已初始化时返回200 `{revisionId:null,revision:null,status:"NOT_CONFIGURED",policyVersion:0,publishedAt:null}`（Runtime仍fail-closed），否则404初始化异常；不返回敏感匹配表达式 |
| POST /api/v1/governance/agent-egress-approvals | `{agentId,providerId,regionCode,approvedClassMax,validFrom,validUntil,reasonCode}` | 201 `{approvalId,status,validFrom,validUntil}`；SecurityApprover，不能自报Agent授予权限 |
| GET /api/v1/governance/agent-egress-approvals | agentId?,providerId?,status?,page,size | 200 Page安全批准元数据；仅Editor/Approver/Admin受控查看 |
| PUT /api/v1/governance/deployment-boundaries/{deploymentId} | `{approvedClassMax,regionCode,validUntil,dataProcessingApproved:boolean,expectedVersion:long\|null,reasonCode}` | 首次201/后续200 `{deploymentId,approvedClassMax,regionCode,securityApprovalStatus,validUntil,version}`；SELF_HOSTED不自动获Confidential |
| POST /api/v1/governance/exceptions | Idempotency-Key + `{agentId,modelCode,ruleCode,reasonCode,validUntil}` | 201 `{requestId,status:"PENDING",version:0}`；仅自己请求误报例外，原始Prompt不得作为reason |
| POST /api/v1/governance/exceptions/{requestId}/review | `{decision:"APPROVE"\|"REJECT",reasonCode,expectedVersion}` | 200 `{requestId,status,version,reviewedAt}`；不能自批、越过hardDeny/RESTRICTED |
| POST /api/v1/governance/exceptions/{requestId}/revoke | `{reasonCode,expectedVersion}` | 200 `{requestId,status:"REVOKED",version}`，现时PREDISPATCH再审 |
| GET /api/v1/governance/decisions | from?,to?,agentId?,decision?,page,size（最多90日） | 200 Page<SafeGovernanceDecisionDTO>，仅返回phase/revision/class/decision/safeRuleCodes/time，不含正文/命中片段/HMAC密钥 |

`RuleV1/EgressV1/OutputRuleV1` **不是任意可执行规则**：只允许由Core编译并审核的固定 `ruleCode` 和严格有界参数 DTO；P6 RuleCode×ParameterSchema 枚举及执行预算已在[治理协议](../protocols/governance.md)第3节定义；真正Scanner代码、边界/失败测试仍须在P6交付，不能把设计候选写成运行通过；实现 AI 不允许根据分类需求自行开放任意 regex 或脚本。Policy身份、Rule变更审批权限和发布状态先于P7出站，不因不知道真实生产敏感词就把所有文本放行。所有JSON错误仍走[API总则](../06-api-design.md)统一安全Envelope，特别是策略不存在时不返回200空规则。

**P6固定双人审批例**：

~~~json
{"decision":"APPROVE","reasonCode":"POLICY_REVIEW_OK","expectedVersion":1}
~~~

对创建者自己调用 `POST /governance/policies/101/review` 必须403或409（明确安全拒绝，不发生任何Published切换/非法日志正文）；不同 Approver审核通过才允许继续 `/publish`，并且 Publish 与 Core 最终 Permit 通过同一已定义的当前策略版本线性化。



## 2. 审核和发布协议补充

- GovernancePolicyRevision与ExceptionRequest各含version。Review请求expectedVersion，成功响应返回新version；发布请求同时校验expectedPolicyVersion和expectedActiveRevisionId。
- 尚无生效Policy时管理GET返回NOT_CONFIGURED+policyVersion=0，不意味着Runtime放行；数据安全仍fail-closed。
- P5 TeamGrant必须持久化issued_reason_code、revoked_by/at/revoke_reason_code；撤销幂等204不退已发资金。
- RuleRegistry是固定受控内置检测器、出站全八格矩阵，不能允许用户上传可执行脚本/任意regex。详见[治理协议](../protocols/governance.md)。
- 管理所有写操作经Core自身当前ROLE+Team鉴权，提交审计与业务状态同一个MySQL事务。

## 3. 检查结论

新增字段已体现于Core V4～V6设计SQL；P4/P5/P6真实约束与安全测试均NOT RUN。
