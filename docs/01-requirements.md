# 01 · Requirements（新项目完整目标）

以下 FR 是**规划设计**而非已实现功能。具体交付批次见 09-roadmap，每个 Phase 的本地 AI 工作单见 10-task-contracts。

| FR-02 | Agent 管理 | 已有 Agent 对应 Application；创建/轮换/撤销独立 API Key，明文只返回一次 |

## 非功能要求

正确性：余额/预留不能负数，重复调用和重复消息不能重复扣费，Team 发放与扣池原子化。未知上游用量不得伪装为 0，安全拒绝不能调用 Provider。
安全性：员工身份证明必须可信；管理角色最小权限；供应商凭证在存储中加密，API Key 只存不可逆摘要；管理端不得默认记录原始 Prompt 或输出。
可靠性：账务成功不依赖 MQ 可用性；RabbitMQ 和 Redis 不可作为权威资金数据库；过期和周重置需并发测试。
性能与规模：用模拟 10k 员工、给定峰值活跃比率与可复现压测环境作容量分析，不事先承诺 10k QPS。记录吞吐、P95/P99、SSE 活跃连接、JVM 资源、MySQL 锁等待。
工程质量：每阶段自动单测、HTTP/事务集成测试、错误路径、CI；不得将旧项目测试证明当成新项目验收。

## 核心业务端到端场景

1. 创建 Team/Employee/Agent/Provider/Model/Deployment、发 Key、授权允许模型并成功调用。
2. 两名员工并发使用相同个人/Team 授额，不得超扣；同一请求幂等重复提交不得再发出付费调用。
3. 团队 B 给团队 A 员工发 1000 积分，B 当时预算记 1000；员工之后用 300 归自己，没用完的 700 过期不返还。
4. 企业限流档收费预算耗尽时，只可调用已经批准且有容量的自部署基础模型，否则拒绝；紧急模式另有事前授权金额。
5. SSE 客户端断开且 Provider 无可信尾部用量，订单转待核对；不直接释放全部风险预留。
6. 高风险 Prompt 在模型出站前被安全政策阻断，不泄漏原文。
7. 成本报表按实际 token 归集到员工，团队发放支出单独展示，不重复合计为公司 Provider 采购成本。
