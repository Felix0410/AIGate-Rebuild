# 02 · Business Rules（最高优先级）

## 身份、权限

每个现有 Agent 一对一对应 Application，持有可撤销的 Agent Key。每个 Employee 有独立可信凭证，**两个身份每次调用都需要验证**；传入 employeeId 不能代替个人认证。Employee 必须有 Agent 使用权，Agent 必须配置逻辑 Model 白名单。降级和紧急不豁免权限与合规。

设计默认：员工随机高熵 Key 只显示一次，仅保存摘要、有效期与撤销状态；管理员/团队负责人/员工/成本读者按角色控制 API。

## 额度

公司统一时区周一 00:00 刷新 Employee×Agent 免费周积分和 Employee 基础周积分，不结转。消费顺序：Agent 免费 → 个人基础 → 有效 Team 授额（最早过期优先）。设计默认时区 Asia/Shanghai，数据库 UTC。

Team Manager 可审批申请或主动跨团队发放；**成功发放的同一 MySQL 事务**扣 issuingTeam 池、生成 recipientEmployee 带有效期 Grant 和流水。余额不足整体拒绝、重复操作幂等。**Grant 到期未用不返还 Team 池**。

## 降级与紧急

正常额度耗尽→公司有 Employee 周上限和企业总池上限的付费保底；进入最低速率/优先级的限流档，切换 Agent 预设且安全获准的低成本逻辑 Model 并通知。保底预算不足时**不继续产生新第三方收费调用**。仅当确有批准的有限容量自部署基础模型时，允许转至其专属受限使用；否则拒绝。紧急任务必须事前审批，指定员工/Agent/任务、有效期、金额、独立企业预算上限，不能突破权限和安全政策。三个流量档为限流/普通/紧急。

## 计价与财务安全

可信 Provider Token 用量分类（输入/输出/缓存）× 调用时有效的内部积分价格＝员工已结算积分；使用供应商采购价另算 Provider 成本估算。**调用前先原子预留最大受控费用风险敞口**，Provider 成功且用量可信才按实际结算并释放差额。无可信用量的超时/SSE 断线→PENDING_RECONCILIATION，不猜测成本为零。无法确定最大可控费用风险的付费请求应拒绝或先补充有界 Provider 约束。

设计默认：积分 DECIMAL(20,6)、供应商金额 DECIMAL(20,8)，每百万 Token 单价、逐请求 HALF_UP 舍入，供应商币种不可混加；最终精度与公式可经审核修订。Provider 网络调用不得持有数据库行锁。

## FinOps 归属

**谁用归谁**：调用消耗归可信 Employee，按调用时其主 Team 快照可汇总。**谁发放谁承担内部额度支出**：Team 成功发放的积分全部计入该 Team 内部预算支出，员工之后使用时不再次扣 Team。公司 Provider 采购成本独立按实际 Token/供应商价估算。**员工使用、Team 发放、Provider 成本三口径不能相加成公司总采购费用**。

例：客服 Team 发 1000 积分给研发 Employee，客服 Team 支出 1000；员工用 300 归员工，余 700 到期不退；公司采购成本另算。

## 模型、安全、SSE

正常模式只在员工所选逻辑 Model 的健康 Deployment 间路由；保底切模型须重新授权。不得无条件重试可能已收费的请求。SSE 增量透传、断连取消、资源有限，尾部 usage 不可信则对账。安全检查重点是**Provider 出站前的请求数据风险策略**，第一版不宣称能撤回已输出的敏感 Token。日志、队列和分析表不默认保存原始 Prompt/回复/明文密钥。网关监控只声明网关观测，不谎称可看到第三方 GPU 负载。
